# 情感陪伴模型项目交接

## 项目与当前状态

参赛题目：数字人综合情感陪伴对话模型。

仓库：https://github.com/Muelsyse516/migu_AI_competition_Emotional_Companion_Dialogue_Model/

当前版本标签：`v5.2-handoff`。

已完成基准测试、多轮训练、模块拆分、完整推理验证，以及官方入口和镜像空间问题修复。用户反馈最新平台测试成功，说明可以跑通，但目前没有官方成绩，不能据此判断排名。

## 当前正式方案

- 情绪识别：Qwen2.5-7B-Instruct，运行时NF4量化，LoRA加16类分类头。
- 回复生成：Qwen2.5-3B-Instruct加reply-v3 LoRA。
- 性格与表达风格：CPU分类器。
- 兴趣识别：BERT分类器。
- 公开输入没有记忆库时，`memory_refs`输出空数组。

采用模块拆分，是因为让一个模型同时生成回复、情绪和画像，早期效果不稳定。各模块可独立改进，但更换后仍需完整回归。

以上都是本地诊断，不是官方分数。不同报告的数据集和计时约定不同，不能直接跨表比较。

## 如何恢复

先阅读正式包中的`HANDOFF_README.md`，核验文件，再在匹配的Linux环境中恢复`/root/participant`。

统一入口：

```bash
bash /root/participant/start.sh INPUT_JSONL OUTPUT_DIRECTORY
```

主要环境版本：

- Python 3.12
- PyTorch 2.10.0+cu128
- Transformers 4.57.6
- Accelerate 1.15.0
- PEFT 0.17.1
- bitsandbytes 0.48.2

需要恢复全部模型、分类器资产和离线依赖，不能只复制权重。正式包内有短样例和核验工具，应先完成短验证，再做完整实验。

## 已踩过的坑

1. 官方推理曾因缺少`/root/participant/configs/inference_config.json`失败。当前版本已补齐配置和兼容入口。
2. 官方曾在`docker load`阶段报空间不足。后来清理旧候选部署目录和下载缓存。镜像加载需要额外空间，不能只看压缩包大小。
3. 多次出现NVML Unknown Error。属于当时GPU访问故障，不能通过重新训练解决。
4. 早期小规模LoRA训练完成，但指标退步。训练成功、loss下降都不等于任务效果提高。
5. 重复惩罚的隐藏默认值曾造成回归，正式版本明确固定为1.05。
6. 7B运行时量化不代表磁盘权重已缩小。换预量化模型需要重新验证质量、兼容性和速度。

## 建议下一步

先复现当前V5，确认入口、模型资产、输出格式和指标一致，建立可回退基线。

然后优先取得官方成绩或具体评测反馈。公开评分包括情绪25分、回复20分、画像15分、速度10分，以及专家评审30分；详细聚合公式尚未完全核实，不应计算虚构总分。

实验优先级：

1. 专项改善性格与表达风格识别。
2. 单独比较更强的量化回复模型，保留现有7B情绪模块作为对照。
3. 对收益明确的候选做完整离线回归和镜像空间验证。

每个采用版本单独提交Git、创建标签、记录数据集、指标、回归问题和资产哈希。未采用实验也保留记录。历史逐轮记录已经补入CHANGELOG，但没有伪造过去的Git提交。
